Munchi

拍一張照，
餵出你的小人。

記錄飲食最難的不是拍照，是「持續」。Munchi 讓 AI 幫你估熱量，再讓畫面中央的小人替你承擔後果：吃垃圾食物會變胖，吃得健康就……拉出一坨彩虹。

📷 拍照或打字記錄 AI 估算熱量 胖瘦即時回饋 Duolingo 式連續紀錄

01 · FEATURES

功能簡介

核心只有一件事：把「記錄」變成「餵養」。每一餐的選擇，都會立刻反映在小人身上。

1拍照 → 判斷 → 算熱量

滷肉飯 · 96%
滷肉飯（中）520 kcal
重新判斷確認
已記錄
拍照／打字→VLM 辨識食物與份量→確認或修改→寫入紀錄

照片或一句「早餐吃了蛋餅和豆漿」送給視覺語言模型，回傳固定格式的 JSON：食物、份量（S／M／L）、熱量與健康標籤。AI 判錯沒關係，確認頁一鍵就能改。

2變胖、變瘦的即時回饋

eat0 預設eat1 胖一次eat2 胖兩次

不健康的一餐體型 +1、健康的一餐 −1，到兩端就停住。角色在 Rive 裡做成狀態機，App 只要觸發對應的 trigger，變胖過程的彈跳動畫由 Rive 負責。

3吃垃圾食物？被漢堡砸！

哇～！
動畫示意（設計稿）

垃圾食物會從畫面外飛過來，正中小人的臉——碰！小人「哇～」一聲往後仰、眼冒金星，然後胖一階。漢堡由 Flutter 依「這一餐的食物」畫出，砸中那一刻再觸發 Rive 的被砸動畫，所以任何食物都能拿來砸。

4吃得健康？拉出彩虹

體型 −1 ✨
動畫示意（設計稿）

健康的一餐會讓小人蹲下、用力、拉出一坨大大的彩虹便便，然後瘦一階，給使用者有趣的正向回饋。

02 · SPEC

規格書

一個循環、一把色尺、三種體型、四種心情、一套架構。

0次確認就能記一餐
0種輸入：拍照 / 打字
0種體型（Rive 觸發）
0階健康量表色

核心循環 CORE LOOP

① 拍照／打字相機、相簿，或一句話描述這一餐
→
② AI 估算VLM 回傳食物、份量、熱量、健康標籤
→
③ 確認／修改不對就改，或按「重新判斷」
→
④ 寫入紀錄存進手機裡的 SQLite
→
⑤ 小人反應體型 ±1、播動畫、更新連續天數

準確度不是重點：熱量直接由 AI 估算，Demo 不建營養資料庫，使用者覺得不對隨時能改。

健康量表色 HEALTH SCALE

很健康雞胸沙拉
健康水果、燕麥
普通蛋餅
不健康滷肉飯
垃圾食物珍珠奶茶

同一把色尺用在：折線圖的點、日曆的每一天、食物卡片、首頁熱量條。每一階的深淺也不同，色弱也分得出來。

技術架構 ARCHITECTURE

Flutter App（iOS，所有資料留在手機）
畫面 · Flutter UI
  • 首頁：小人、今日熱量條、Feed 按鈕
  • 紀錄頁：月份切換、熱量折線圖、健康色日曆
  • 詳細紀錄：由下升起的面板、左右換日
  • 設定頁：每日目標、語言、匯出 / 清除
  • 拍照記錄頁：相機、相簿、打字輸入
Rive 小人 · character.riv
  • State Machine 1 控制所有動畫
  • Data Binding：eat0／eat1／eat2 切換體型
  • App 端只負責「觸發」，動畫由 Rive 播
  • 規劃中：被砸、彩虹大便、心情
AI 服務 · AIService
  • 照片或一句文字 → 送出請求
  • JSON schema 強制回傳格式
  • 解析成食物、份量、熱量、健康標籤
  • 失敗時可重試，或直接手動填熱量
本地資料 · SQLite + drift
  • meal_logs：每一餐、時間、總熱量、健康標籤
  • meal_items：食物名稱、份量、熱量
  • state：體型、心情、連續天數
記一餐的資料流
拍照／打字→AIService→確認頁→SQLite→計算體型→觸發 Rive
VLM API唯一的外部服務：看照片、讀文字、估熱量金鑰放 secrets.json，不進 Git後台設每月花費上限

心情：連續紀錄 DUOLINGO-STYLE

開心最近一餐有準時記
普通還沒到下一餐
焦慮用餐時段過了還沒記
難過整天沒記，連續天數歸零

AI 回傳格式 STRUCTURED OUTPUT

{
  "items": [
    { "name": "滷肉飯", "portion": "M", "kcal": 520 }
  ],
  "health_tag": "normal"   // healthy / normal / unhealthy
}

用 JSON schema 強制格式，份量和健康標籤只能從固定選項挑，App 端不用猜。

05 · DEVELOPMENT

程式設計流程

原則：先讓最小的一條流程跑通，再加功能；每一步都要有能驗證的方法。

01如何開工

  1. 規格書先定 Demo 範圍：做什麼、不做什麼（不上架、不做帳號）
  2. Rive 先做角色：體型與 eat0～eat2 觸發
  3. Flutter 骨架：flutter create＋rive 套件
  4. 先做測試頁：自動列出 .riv 的所有屬性，確認角色能動，再接首頁

02程式管理

munchi_app/      # GitHub repo
├─ lib/           # 畫面與邏輯
├─ assets/
│  └─ character.riv  # Rive 角色
├─ pubspec.yaml
└─ .gitignore     # 擋掉金鑰與產生檔
  1. App 與角色同一個 repo：Rive 匯出的 .riv 直接放進 assets/；介紹網頁另外用 GitHub Pages 發布
  2. 金鑰不進 Git：secrets.json 寫進 .gitignore，執行時用 --dart-define-from-file 帶入
  3. 小步修改：Claude 改檔前先讀現況，一次只改一件事

03如何驗證

  1. 靜態檢查：flutter analyze 必須 0 錯誤
  2. 角色檔驗證：用 Rive Renderer 實際播放 .riv，依序觸發 eat0→eat2→eat0 截圖比對（抓到「頭部描邊沒被匯出」）
  3. 模擬器實跑：iPhone 模擬器跑完整流程
  4. 設計對照：截圖和完稿並排檢查
